## 1. 产品定位

### 1.1 做什么
把 A 股投资中**可以结构化的部分**做到极致：
- 数据获取与清洗（量价、财报、资金流、龙虎榜）
- 技术面与基本面指标的机械计算
- 信号综合评分 + 置信度
- 风控门禁（仓位 / 止损 / 交易频率）
- 模拟盘记账、回测
- 可选的券商下单桥接（默认关闭）

### 1.2 不做什么
- 不做择时预测（"明天涨还是跌"）
- 不做行情直播或高频 tick 级操作（LLM 调用成本和延迟都不适合）
- 不做涉及内幕消息、题材炒作的"跟庄"建议
- 不保证任何收益数字
- 不做融资融券、期权、期货、加密货币——复杂度和风险曲线不一样

### 1.3 核心价值主张
**"让用户少做错事"** > "让用户多赚钱"。纪律固化到代码里，系统拒绝超限操作，用户不可能在情绪上头时 all-in 一只票。

## 2. 用户与场景

### 2.1 目标用户画像
V1 只服务一类用户：**有本金 5 万 - 500 万、每周愿意花 2 小时研究股票、想把纪律托管给工具的散户**。不服务职业交易员（他们有更专业的工具）、不服务完全不懂股票的新手（强 KYC 门槛）、不服务想"一夜暴富"的投机者（会反向引导）。

### 2.2 典型场景

**场景 A：晚上回家复盘**
用户打开 Cowork，说 "今天大盘怎么样，我的持仓有啥要处理的吗"。Skill 拉当日行情和用户持仓，生成：大盘状态 → 持仓健康度 → 触发的风控事件 → 明日关注点。

**场景 B：看到一只票，犹豫买不买**
用户："帮我看看 贵州茅台 600519，现在能加仓吗"。Skill 跑完整分析流程 → 给出评分、买卖建议、建议价位区间、止损止盈、建议仓位、**以及不建议买入的反面理由**。

**场景 C：想系统化选股**
用户："从沪深 300 里帮我选 10 只有色金属业绩可能改善的"。Skill 按用户口径筛选，返回 Top 10 + 风险提示。

**场景 D：做一个策略回测**
用户："帮我回测 MA20+RSI 这个策略过去 3 年在 000858 上的表现"。Skill 跑向量化回测 → 输出净值曲线、夏普、最大回撤、胜率，并主动标注是否有过拟合嫌疑。

**场景 E（可选，默认关闭）：真实下单**
用户显式开启实盘模式 + 填好券商凭证后："按刚才的建议，买入 茅台 10 股"。Skill 再次跑风控 → 打印订单预览 → 等用户回复"确认" → 调券商 API → 推送结果。

### 2.3 明确拒绝的场景
- "帮我看 XX 币"（加密货币不在范围）
- "你觉得 XX 股票明天涨不涨"（不做点预测）
- "帮我买涨停板"（追涨杀跌倾向，skill 会劝阻）
- "我满仓了，再加一点吧"（会触发总仓位闸门）

## 3. 功能需求

### 3.1 功能列表（MoSCoW）

| ID | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 实时/日线行情获取（AkShare） | Must | 免费、无 key |
| F2 | 财报与估值数据 | Must | AkShare 或 Tushare |
| F3 | 技术指标计算（MA/EMA/MACD/RSI/KDJ/BOLL/ATR/量价） | Must | 用 pandas，不强依赖 TA-Lib |
| F4 | 基本面评分（ROE/毛利率/负债率/业绩增速/PE-PB 分位） | Must | |
| F5 | 信号综合评分（0-1）+ 置信度 + 理由链 | Must | 必须含反面理由 |
| F6 | 风控闸门：仓位/止损/单笔限额/日交易次数/冷静期/ST 拉黑 | Must | 代码强制，LLM 不能绕过 |
| F7 | 模拟盘记账（SQLite） | Must | 默认开启 |
| F8 | 单标的 / 策略回测 | Must | 向量化实现，禁止未来函数 |
| F9 | 每日复盘报告 | Should | 由用户或定时任务触发 |
| F10 | 持仓健康度扫描 | Should | |
| F11 | 自选股管理（watchlist.yaml） | Should | |
| F12 | 券商下单适配器（QMT / Futu / easytrader） | Could | 默认关闭，用户显式开启 |
| F13 | Telegram / 钉钉 / 邮件推送 | Could | 不作为核心流 |
| F14 | 多模型路由 | Won't (V1) | 维护成本远超收益 |
| F15 | 日内 tick 级策略 | Won't | 超出 LLM 合适工作节奏 |

### 3.2 风控硬约束（不可配置绕过的部分）

代码层面永远强制：

1. ST、*ST、退市整理股默认不下单（可分析）
2. 涨停板不买入（买单会被拒，避免 T+1 被套）
3. 跌停板不卖出（卖单无意义）
4. 9:15-9:30 集合竞价窗口不自动下单（流动性差）
5. 真实下单必须用户发送精确字符串 `"确认"` 才执行
6. 单笔、单股、总仓位任意一项超限 → 立即拒绝
7. 相同股票 5 分钟内不得重复下单（防误触）
8. 交易日外的时间只记录信号不下单

这些是 V1 就有的硬约束，不放在 yaml 里让用户改。

### 3.3 风控可配置约束（用户可通过 yaml 调整）

| 参数 | 保守默认 | 稳健默认 | 激进默认 |
|---|---|---|---|
| 单只股票最大仓位 | 10% | 20% | 30% |
| 总仓位上限 | 50% | 80% | 100% |
| 单笔最大金额 | 账户 5% | 账户 10% | 账户 15% |
| 单股止损线 | -5% | -7% | -10% |
| 单股止盈线 | +15% | +20% | +30% |
| 日内交易上限 | 2 笔 | 5 笔 | 10 笔 |
| 冷静期 | 30 分钟 | 10 分钟 | 5 分钟 |
| 最低流通市值 | 200 亿 | 50 亿 | 无 |
| 是否允许 ChiNext/STAR | 否 | 是 | 是 |

### 3.4 API / 集成需求

| 类别 | V1 选型 | 获取门槛 | 备用 |
|---|---|---|---|
| LLM | Anthropic Claude Sonnet 4.6 | 网上充值、国内信用卡或中转 | Claude Haiku 4.5（省成本的简单任务） |

## 4. 非功能需求

### 4.1 性能
- 单只股票完整分析（数据 + 指标 + 信号 + 风控）≤ 10 秒（不含 LLM 推理）
- 50 只股票批量扫描 ≤ 2 分钟
- 回测 1 只股票 3 年日线 ≤ 5 秒

这些是**算力约束**，不是 SLA 承诺。网络抖动、数据源波动会影响。

### 4.2 可靠性
- 数据源失败时自动降级（AkShare → Tushare → 缓存 → 失败）
- 下单接口失败时：不重试；打日志；通知用户
- 所有交易决策有完整链路可追溯（`data/trade_log.jsonl`）

### 4.3 安全
- API Key 只读环境变量，不写入代码/文件
- `config/risk.yaml` 不含凭证，只含参数
- `config/secrets.yaml`（如需要）默认加入 `.gitignore`
- 券商下单前必须二次确认
- 所有风控拒绝事件写日志

### 4.4 合规
- 不使用任何爬取受限数据的接口
- 不宣称预测能力
- 每份分析报告在文案末尾附"本内容非投资建议"免责声明
- 不存储用户券商密码；只存储 access token / session cookie（短期）

## 5. 架构简述

详见 `docs/architecture.md`。此处仅概要：

单进程 Python 应用 + SKILL.md 作为 LLM 行为规范。不搞多 Gateway / 多 Agent 的分布式架构——那是对 V1 的过度设计，维护成本远超收益。

LLM 就是"编排者"：根据用户输入决定调哪个脚本、合成输出。Python 脚本是"工具箱"：确定性的、可单元测试的、不依赖 LLM 的纯函数。

## 7. 成功指标（工程 KPI，非盈利 KPI）

**明确区分**：工程交付的 KPI 和投资盈利的 KPI 不是一回事。Skill 的成功只负责前者。

工程交付 KPI：
- Skill 安装后 10 分钟内跑通第一个分析请求
- 单元测试覆盖率 ≥ 80%
- 风控拒绝率：模拟盘 3 个月内拒绝事件 ≥ 1 次（证明闸门在工作）
- 无越权事故：真实下单 0 次"未经用户确认就执行"

投资盈利 KPI（由用户自己评估，skill 不对此负责）：
- 用户自行在 3 个月模拟盘验证后决定是否上实盘
- 参考但不承诺：跑赢对应基准（沪深 300 / 创业板指）

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 用户把 skill 当"必赚神器" | SKILL.md 和每次输出都强调不确定性；加强免责 |
| LLM 输出幻觉导致错误信号 | 所有"硬决策"走 Python 脚本；LLM 只负责呈现 |
| 数据源限流 / 返回异常 | 异常捕获 + 降级路径 + 缓存 |
| 用户配置错误导致大额损失 | 硬约束不可配；软约束默认保守 |
| 监管变化（程序化交易备案等） | 不做 HFT，不触发备案门槛；skill 文档提示用户注意合规 |
| 券商接口变更 | 适配器隔离；接口失败不重试 |
| 模型 API key 被盗用 | 环境变量隔离；建议启用 API 使用量告警 |
